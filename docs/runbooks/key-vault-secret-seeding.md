# Seed the two hand-written Key Vault secrets

Two credentials the platform reads at runtime are never generated by Terraform:
Argo CD's OIDC client secret and the Cloudflare API token. Terraform creates
both secret objects in Key Vault holding a placeholder string, and the values
are written once, by hand, by Hari. This runbook is that hand step.

Terraform is kept out of the values on purpose. A client secret it generated
would sit in Terraform state in clear text, so the credential would exist in
two places instead of one. The Cloudflare token predates every cluster and
every state file, so Terraform could not have produced it anyway. What
Terraform owns is the shape: the two secret names the cluster reads, and the
data-plane role assignment that lets a secret be written at all.

Perform this once, after the first `terraform apply` of the persistent layer.
Repeat only to rotate a credential.

## Before you start

- The persistent layer has been applied at least once, so the vault and the two
  placeholder secrets exist.
- You are signed in with `az login` as an account holding the Key Vault Secrets
  Officer role on the platform vault. Terraform grants that role to the
  principal it runs as, not to you, and Subscription Owner is not enough: the
  vault uses Azure RBAC for its data plane, where control-plane ownership
  carries no right to read or write a secret.

## Collect the inputs

The vault name and the Argo CD client ID come from Terraform outputs, so start
in the layer directory. Every command below uses one value or the other.

```shell
cd infra/persistent
VAULT_NAME=$(terraform output -raw key_vault_uri | sed 's|https://||; s|\..*||')
ARGOCD_CLIENT_ID=$(terraform output -raw argocd_client_id)
```

## Seed the Argo CD OIDC client secret

1. Generate a client secret on the Argo CD app registration. Azure prints the
   generated value once and never again, so capture it into a shell variable
   rather than reading it off the screen:

   ```shell
   ARGOCD_CLIENT_SECRET=$(az ad app credential reset \
     --id "$ARGOCD_CLIENT_ID" \
     --display-name "argocd-sso" \
     --years 1 \
     --query password --output tsv)
   ```

   `credential reset` replaces the registration's existing secrets. On a first
   seed there are none; on a rotation, every secret already issued for this
   registration stops working the moment the command returns.

2. Write it into the vault:

   ```shell
   az keyvault secret set \
     --vault-name "$VAULT_NAME" \
     --name argocd-oidc-client-secret \
     --value "$ARGOCD_CLIENT_SECRET" \
     --output none
   ```

3. Clear the value from the shell:

   ```shell
   unset ARGOCD_CLIENT_SECRET
   ```

4. If you are rotating rather than seeding, restart the Argo CD server pods so
   they re-read the secret. External Secrets Operator refreshes the Kubernetes
   secret on its own schedule; Argo CD does not watch it.

## Seed the Cloudflare API token

1. In the Cloudflare dashboard, create an API token scoped to the platform
   zone with exactly two permissions: `Zone - DNS - Edit` and
   `Zone - Zone - Read`. Both are required by cert-manager's DNS-01 solver,
   which lists zones before it writes the challenge record; external-dns writes
   its records in the same zone with the same token.

2. Write the token into the vault, pasting it at the prompt so it does not
   enter shell history:

   ```shell
   read -rs CLOUDFLARE_API_TOKEN
   az keyvault secret set \
     --vault-name "$VAULT_NAME" \
     --name cloudflare-api-token \
     --value "$CLOUDFLARE_API_TOKEN" \
     --output none
   unset CLOUDFLARE_API_TOKEN
   ```

## Confirm the seeding took

Each secret should carry a version newer than the placeholder Terraform
created. Print the timestamp, never the value:

```shell
az keyvault secret show --vault-name "$VAULT_NAME" \
  --name argocd-oidc-client-secret --query attributes.updated --output tsv
az keyvault secret show --vault-name "$VAULT_NAME" \
  --name cloudflare-api-token --query attributes.updated --output tsv
```

A timestamp later than the apply that created the vault means the hand-written
value is current.

## What not to do

Do not change `value_wo_version` in `infra/persistent/secrets.tf`. Terraform
writes a secret only when that number changes, which is what leaves your
hand-written value alone. Bumping it makes the next apply overwrite a live
credential with the placeholder string, and the first symptom is Argo CD
refusing every login or cert-manager failing its DNS-01 challenge.

Do not put either value into a Terraform variable, a tfvars file, or the repo.
Rotation is a Key Vault write, and nothing else needs to change.
